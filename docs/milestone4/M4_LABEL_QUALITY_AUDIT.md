# SafeHER M4 — Label Taxonomy and Dataset Audit Procedure

**Document type:** Research design / audit procedure, not a completed empirical dataset audit.\
**Last reviewed:** 25 November 2026

## Current evidence status

The supplied project archive contains label-taxonomy and adjudication code, but no populated M4 training dataset or image manifests. Therefore this document defines how labels should be reviewed; it does not claim that external datasets were inspected, that any defect rate was measured, or that a dataset is approved for training.

## 1. Label taxonomy

Keep distinct manipulation histories separate. A source dataset's original label must be preserved verbatim alongside any normalized SafeHER label.

| Normalized label | Meaning | Model A eligibility | Model B eligibility |
|---|---|---|---|
| `FULLY_AI_GENERATED` | Entire image generated by a generative model | Candidate positive class, after provenance review | Not automatically applicable |
| `PARTIALLY_AI_GENERATED` | Image contains a mixture of generated and non-generated regions | Separate task or exclude from binary training | Only where annotated face manipulation is present |
| `FACE_SWAPPED` | Facial identity region replaced or transferred | Usually not a full-image AI-generated label | Candidate positive class |
| `FACIAL_REENACTMENT` | Facial expression or motion altered | Usually not a full-image AI-generated label | Candidate positive class |
| `FACE_INPAINTING` | Local facial region generated or replaced | Usually not a full-image AI-generated label | Candidate positive class when region annotation exists |
| `GENERAL_IMAGE_EDITING` | Non-generative editing or compositing | Separate task; do not conflate with AI generation | Not eligible unless facial manipulation is annotated |
| `RETOUCHED_GENUINE_PHOTOGRAPH` | Genuine photograph with ordinary post-capture retouching | Candidate negative class only with reliable provenance | Candidate negative class only with reliable provenance |
| `UNKNOWN_MANIPULATION_HISTORY` | Modification suspected but source history is unknown | Quarantine / do not use as clean ground truth | Quarantine / do not use as clean ground truth |
| `INSUFFICIENT_ANNOTATION_EVIDENCE` | Evidence does not support a reliable label | Exclude from supervised loss; retain audit record | Exclude from supervised loss; retain audit record |

Eligibility is a design rule, not a statement that training data is currently available.

## 2. Required per-dataset audit

Before admitting any dataset, record and inspect:

1. Exact upstream release, version, acquisition method and sample count.
2. License text, commercial-use restrictions, attribution and derivative-model terms.
3. Consent and use restrictions, where applicable.
4. Original publisher labels and normalization rules.
5. Provenance, parent image/video, subject/source grouping and generator lineage.
6. Exact and near-duplicate clusters across train/validation/calibration/test splits.
7. Ambiguous labels, missing source pairs, corrupted files and annotation disputes.
8. Trainability and task-specific eligibility decisions with reviewer and timestamp.

Do not infer dataset rights from a project README alone. Verify the actual license and terms that govern the data files and model use.

## 3. Adjudication procedure

- Preserve the original publisher label.
- Normalize only with an explicit, versioned mapping rule.
- Use at least two independent reviewers for high-impact ambiguous cases where feasible.
- Record agreement, disagreements, evidence basis and final adjudication.
- Quarantine unresolved items instead of forcing a binary label.
- Never silently discard difficult evaluation samples; report excluded and abstained counts.
